Project facts (sourced 20261109, updated the same day)
- Program file: imapidle. Perl, ISC header, Copyright (c) 2026 Todd T. Fries. Renamed from imap-idle-notify. ~/bin/imap-idle-notify is still the old copy and has not been replaced.
- Invocation: imapidle [-dv] [-c file]. Default file ~/.config/imapidle/imapidle.conf. -d stays in the foreground and copies logs to stderr. -v logs `* OK Still here` and `IDLE re-armed`. Those two stay quiet by default (2026-11-10).
- Manuals: man/imapidle.1 and man/imapidle.conf.5. mandoc -Tlint is silent. Sibling pages are named with Sy because they are not in /usr/share/man yet.
- Test command: make test (prove t). The suite is t/00-syntax.t through t/16-wake-signal.t. t/01-mandoc.t runs mandoc -Tlint. t/12-track.t covers tracking, the mbsync cap, pause, and shutdown. t/13-secret.t covers pass_cmd backoff. t/14-io-timeout.t covers the 45s waits. t/15-tls-save.t covers the certificate and negotiation archives. t/16-wake-signal.t covers SIGCHLD blocked outside pselect. Those tests do not start a live IMAP server or a live mbsync.
- Purpose: watch IMAP folders and fork /usr/local/bin/mbsync <channel> when the server reports a change. OpenBSD isync is one-shot.
- History came from ~/bin (11 commits, 2026-04-07 through 2026-06-07). Hashes here differ because those commits used to sit inside the bin repo.
- Config: Config::Tiny (p5-Config-Tiny 2.14). Not Config::IniFiles. Any account missing server, user, mbsync_channel, or exactly one of pass or pass_cmd exits 1 before the loop. The reason is printed to stderr. No accounts from that file are kept.
- Secret: exactly one of pass or pass_cmd. The names password and password_cmd are not read. pass_cmd is /bin/sh -c, first stdout line, exit 0, 30s budget, rerun on each connect. Output is not logged. A failure waits 60 seconds and doubles that wait up to 21600. `name: pass_cmd failed` is logged on the first failure and then only after 86400 seconds. A later success logs `name: pass_cmd recovered` once. The account is not disabled for this failure, and the command text stays out of the log (2026-11-11). OAuth is not implemented; the command prints the secret. A missing required key exits 1 before the daemon starts and loads no accounts.
- State files live in ~/.local/imapidle/ (directory mode 0700, files mode 0600). The config stays ~/.config/imapidle/imapidle.conf. If known_hosts or learned is missing there and the same name exists beside the config, it is copied once. The log is `copied BASENAME to DIR`. The old path is not deleted. known_hosts is a SHA256 fingerprint. An unknown certificate is stored with no prompt. A changed fingerprint is kept, with a third field YYYYMMDDTHH:MM:SSZ (GMT) marking when it was retired; only one line per host has no retired time (2026-11-10). The first look at a host logs [cert] NN: host:port tls fp match|new|change, plus +fp for new and change, and -fp for change. Later connections to that host do not repeat it (2026-11-11).
- TLS: IO::Socket::SSL with SSL_VERIFY_NONE, then that TOFU check. IO::Socket::SSL 2.099 is installed. TCP connect and the TLS handshake share a 45s deadline. Sockets stay non-blocking. Each IMAP read or write waits at most 45s and polls the other connections and mbsync while it waits (2026-11-12). A finished handshake is also archived under certs/YYYY and tls-negotiations/YYYY. The file name is the SHA1 of its bytes, a hyphen, and host:port. certs/ holds the chain in the openssl s_client -showcerts form. tls-negotiations/ holds the client offer and the selected parameters. Ephemeral keys and tickets are omitted so the same server stays one file until the client or the server changes the handshake (2026-11-12). SIGCHLD and SIGINFO stay blocked except inside pselect. OpenBSD malloc aborts if a Perl handler runs while malloc is already on the stack; a burst of mbsync exits did that (2026-11-12).
- IMAP: Mail::IMAPClient 3.43. idle, idle_data, and done exist. NOTIFY is sent on the socket that stays in the select set. Otherwise one IDLE connection per folder. The first connection of an account is primary. On that socket, after login, imapidle sends `ID ("name" "imapidle" "version" "0.1")`, CAPABILITY, and LIST only when the saved record says each one is due, then NOTIFY or IDLE, and stays up. Extra IDLE sockets do not send those three. A host's NOTIFY result is stored in ~/.local/imapidle/learned: absent, rejected, or active, plus an optional server id. An old line of host, notify, and optional id still loads. It does not request CAPABILITY only because the later fields were added. The next primary connection does send ID once. absent and rejected skip NOTIFY on later connections, including other accounts on that server:port, and do not repeat the discovery log. active still sends NOTIFY SET each session and logs again only when the result changes. The ID reply is hashed with keys and values sorted. NIL hashes as NIL. A different hash logs `host:port: id updated (xN avg S.SSs)`, requests CAPABILITY, and halves the ID interval. The first stored hash does not force CAPABILITY. NO or BAD is recorded as ID unsupported and is not a new hash on every try. Three unchanged checks double the interval. The floor is min (600 seconds). The ceiling and the capability backstop are both capability (604800, one week). Delete the host line to probe both again. The same server:port shares one row (2026-11-11).
- mbsync: /usr/local/bin/mbsync channel:box [channel:box ...]. isync-1.5.1p0 is installed. The summary line is summary() in src/main_sync.c of isync 1.5.1. Same-channel folders that are ready within one 5s window share that argv. wait seconds (the max in the batch) happen in the child after the 5s. Child closes inherited descriptors. A bare channel and channel:box for that same name do not run together (2026-11-10). [track] connections defaults to 2 and counts mbsync children only, not IMAP sockets. When connections is above 1 and a pulse channel is due, named folders keep one slot and pulse uses the others, so one long named sync does not hold every pulse channel. With connections 1, pulse waits while a named folder is queued or syncing. When no pulse channel is due, hot folders may use every slot, and tracked mailboxes and pulse channels leave one slot free when the limit is above 1. With connections 1, a tracked or pulse job starts only when nothing hot is due and nothing is running. Order is hot, then the oldest due tracked mailbox, then pulse. A tracked argv is one channel:box. Its stdout is read for the last Channels summary. New messages are Far+ plus Near+. isync prints the progress counters only on a tty, so a pipe does not include them. Stderr is discarded. Hot and pulse children still send stdout and stderr to /dev/null. On exit one line starts with the channel and a colon, then mbsync, any mailboxes, the pid, status or signal, and the time -l figures collected with wait4: real user sys, rss kilobytes, minflt, majflt, inblock, oublock, nvcsw, nivcsw. The same argv keeps a count and a total of real seconds in ~/.local/imapidle/mbsync-real. The key is the sha1 -b token of that command. An older base64 key is still read. The file is loaded at startup. The line ends with `(xN avg F)` where N is the count after this run and F is total/N. Exit 0 is info. Any other exit is a warning (2026-11-11).
- Connection time is a separate table in ~/.local/imapidle/conn-time. The key is the account and the folder for IDLE, or the account and notify for NOTIFY. On drop the line is `name: disconnecting WHAT (xN avg S.SSs)` (2026-11-11).
- Syslog: ident imapidle, options cons,pid, facility mail. Account and channel lines start with that name, left-aligned so the colon is one column, as in `fdc-list: * 2058 EXISTS`, `fdc-list: 0.start <sha1-b>=[N] INBOX.2026-11 guestimate 2s ending at 20261112 16:07:06`, and `fdc-list: 0.stop  <sha1-b>=[N] INBOX.2026-11 ret 0 xN cur|avgs cur|avgrss`. The number before start and stop is the connection slot in base 36 (0-9 then a-z), assigned when that mbsync is forked and repeated on its stop line. A slot at or past the connections count means one start too many. The guestimate is the saved average real seconds of that command, rounded, and the local time that many seconds after the fork. A command with no saved average yet leaves the clause off (2026-11-12). Config errors still name the section in brackets.
- After startup, a failed account, socket, pass_cmd, or mbsync does not exit the process. The loop exits 0 on SIGTERM, SIGINT, or a file ~/tmp/shutdown, ~/tmp/shutdown.mail, or ~/tmp/shutdown.imapidle. The handler sets a flag and does not exit. When that shutdown is noticed, each open IDLE session is ended with DONE and then LOGOUT, and each NOTIFY session with LOGOUT. A session that is already dead is closed without those commands (2026-11-12). In-flight mbsync then finishes, stats are written, and the log says `shutdown complete`. SIGHUP re-reads the config on the next wake (within about 30s), marks every folder list due, and does not exit. A bad file is logged and the running accounts stay. Server, port, user, secret, or channel changes reconnect that account. Folder names and priorities apply in place; a new folder without NOTIFY is connected on that wake. SIGINFO (Ctrl-T) prints state to stderr when -d, and to syslog when daemonized: accounts, connections, per-folder priority and mbsync timing, pulse channel clocks, one tracked line per channel (each mailbox when -v), and mbsync children. An account that has never monitored a mailbox is paused after 5 consecutive failures. The first pause is 1800s. The failure count and the connect backoff are reset, and it tries again when the pause ends. Another five failures pause for one and a half times as long, rounded. A step that would pass 43200s is not taken, so the pause stays on the last step under 12h. A successful monitor clears that ladder. SIGHUP enables it and starts the ladder over at 1800s (2026-11-12). A failing pass_cmd does not count toward those five and does not use that backoff. An account that has monitored keeps backoff (5s, x1.5, cap 900). Backoff does not sleep the other accounts. A failed mbsync does not disable the account.
- A file ~/tmp/pause, ~/tmp/pause.mail, or ~/tmp/pause.imapidle lets a running mbsync finish and starts no new hot, tracked, or pulse mbsync. IMAP, LIST, IDLE, and NOTIFY continue. The log says `pause file PATH detected, idling operations` once, then `pause cleared, mbsync resuming` when all three are gone. Events stay queued and catch up after that. A shutdown file wins over pause (2026-11-11).
- IDLE is refreshed about every 30s with DONE then IDLE. NOOP is not sent during IDLE. NOTIFY connections get NOOP on that timer. The re-arm notice and `* OK Still here` are logged only with -v (2026-11-10). A failed re-arm is still a warning. DONE, IDLE, and LOGOUT are not sent once the socket is already dead, so Mail::IMAPClient does not dump a not-connected stack (2026-11-12).
- Priority is the minimum time between mbsync runs for one folder (2026-11-10): 1 or less → 7s; 2 → 42s; 3 → 128s; 4 → 256s; >=9 → 3600s; else 180+(priority-3)*120, so 5 is 420, 6 is 540, 7 is 660, and 8 is 780. A ready folder's event opens a 5s channel window (not restarted by later events). An event inside the minimum gap stays pending and is scheduled when the gap ends, with no extra 5s unless another folder's window is already open. No event during the gap leaves the folder ready for the next event. IDLE keepalive (`* OK Still here`), continuations, and tagged replies do not schedule mbsync. The keepalive and the re-arm notice are logged only with -v. Continuations and tagged replies stay in the log. EXISTS, EXPUNGE, FETCH, RECENT, VANISHED, and STATUS do. DONE/IDLE refresh is about every 30s, not on every read.
- wait (seconds, default 0) sleeps in the mbsync child after the 5s combine, not in the IMAP loop.

Config shape the script reads
- One INI section per account. Required: server, user, mbsync_channel, and exactly one of pass or pass_cmd. port defaults to 993. Missing required keys exit 1. disabled = yes keeps the section without connecting or checking those keys. Any other value leaves it active. SIGHUP leaves a yes section disabled until yes is removed (2026-11-10). auth is login (default) or xoauth2. xoauth2 sends AUTHENTICATE XOAUTH2 with the pass or pass_cmd value as the bearer token. The token is not logged.
- folder0, folder1, ... value is NAME or NAME;priority=N. Numbers start at 0 and have no gaps. Only the priority suffix is read. Missing suffix → priority 5.
- If no folderN keys: folder (default INBOX) and priority (default 5).
- Every folder in a section shares that section's mbsync_channel.
- [pulse] is not an account. The name pulse is reserved. sweep defaults to 3600. channel0, channel1, ... have no gaps. Each value is one mbsync channel with no mailbox. On load a channel with no row in ~/.local/imapidle/pulse-last is due; a saved exit waits sweep seconds from that time, including after a restart. At startup each enabled account queues its folderN mailboxes. When connections is above 1, one mbsync slot stays with those folders and pulse uses the others. With connections 1, pulse waits until the named sync is done. A reload does not queue them again. After a run exits, that channel waits sweep seconds. Channels run in parallel. A still-running name is not started again. disabled = yes holds the section without checking keys. SIGHUP keeps a remaining channel's clock, makes a new channel due, and uses a new sweep when a run exits. A file with only this section is valid (2026-11-10). Pulse channels that are not imapidle accounts stay whole-channel sweeps. Tracking never runs a bare channel name.
- [track] is not an account. The name track is reserved. With no section the defaults are in force and tracking is on. A present section overrides only the keys it sets. disabled=yes stops tracked syncs. connections still caps hot folders, tracked mailboxes, and pulse channels. Keys: min 600, messages 5, initial 1800, max 21600, list 259200, id 604800, capability 604800, connections 2. min, list, id, and capability must be at least 60. max must be at least min. capability must be at least id. messages and connections must be at least 1. initial is not on the 60-second list. A bad value rejects the file the way a bad sweep does. Mailboxes that are not in folderN are listed on the primary connection. Names stay as the server spelled them. \Noselect and \NonExistent are skipped. A colon in the name is stored and not tracked, because the mbsync argument splits on the first colon. INBOX matches a hot folder either way. The first save with no prior file logs `channel: N folders, list saved` and does not log each name. Later lists log `channel: folder NAME added` or `removed`. A removed name is not synced until a later list adds it. A failed LIST keeps the set and retries after initial seconds. A non-zero tracked mbsync and SIGHUP also request a list. Intervals live in memory and start again from initial after a restart. Names persist in ~/.local/imapidle/folders/<channel>, one escaped name per line. Every three samples of new messages, sync seconds, and the interval those messages arrived in, the wait after mbsync exits is replaced. No new messages doubles it. Otherwise the next wait is the larger of messages times total span over total messages, and three times the average sync. When that result is longer than the current interval, one quarter of the added seconds is X and an unseeded rand() value modulo X is added so mailboxes that share the math do not share a wake time. On this OpenBSD perl the first unseeded rand() is seeded from arc4random(); later values come from that generator. srand(N) would select srand48_deterministic, so the spread does not call srand (2026-11-12). The result is clamped to min and max and rounded to a whole second. Two new messages on each of three 1800 second checks, with a 400 second sync, lands on 4500 before that spread: the message target wins over the 1200 second cost. Thirty new messages with that same sync lands on 1200. Three finishes with no Channels line double the interval, add the same spread, and clear the window. One such finish leaves the interval. A non-zero exit that still printed a summary is a real sample, and that channel's list is due again (2026-11-11).

Removed from the imported script (2026-11-09)
- The 2026-06-07 `exit(1)` before idle_data is gone. A ready socket with no IMAP object is dropped and that account is retried. Mail::IMAPClient 3.43 does have idle_data. The old syslog line was an undefined object, which left the socket readable and spun.
- NOTIFY is armed on the connection that is kept. A rejected NOTIFY falls back to IDLE on fresh sockets.
- Dovecot 2.2 still has no special case in the source. The first probe sends `ID ("name" "imapidle" "version" "0.1")`, then CAPABILITY. A server that rejects NOTIFY is recorded rejected. Later connections stay on IDLE and do not send NOTIFY again. CAPABILITY waits for the one-week backstop. An older learned line is not treated as a software change (2026-11-11).
