Project facts (sourced 20261109, updated the same day)
- Program file: imapidle. Perl, ISC header, Copyright (c) 2026 Todd T. Fries. Renamed from imap-idle-notify. ~/bin/imap-idle-notify is still the old copy and has not been replaced.
- Invocation: imapidle [-d] [-c file]. Default file ~/.config/imapidle/imapidle.conf. -d stays in the foreground and copies logs to stderr.
- Manuals: man/imapidle.1 and man/imapidle.conf.5. mandoc -Tlint is silent. Sibling pages are named with Sy because they are not in /usr/share/man yet.
- Test command: make test (prove t). t/00-syntax.t, t/01-mandoc.t, t/02-config.t, t/03-isolate.t.
- Purpose: watch IMAP folders and fork /usr/local/bin/mbsync <channel> when the server reports a change. OpenBSD isync is one-shot.
- History came from ~/bin (11 commits, 2026-04-07 through 2026-06-07). Hashes here differ because those commits used to sit inside the bin repo.
- Config: Config::Tiny (p5-Config-Tiny 2.14). Not Config::IniFiles. Any account missing server, user, mbsync_channel, or exactly one of pass or pass_cmd exits 1 before the loop. The reason is printed to stderr. No accounts from that file are kept.
- Secret: exactly one of pass or pass_cmd. The names password and password_cmd are not read. pass_cmd is /bin/sh -c, first stdout line, exit 0, 30s budget, rerun on each connect. Output is not logged. OAuth is not implemented; the command prints the secret. A missing required key exits 1 before the daemon starts and loads no accounts.
- known_hosts sits next to the config file. SHA256 fingerprint, accept on a tty, refuse otherwise. New files use mode 0600. Directory created mode 0700.
- TLS: IO::Socket::SSL with SSL_VERIFY_NONE, then that TOFU check. IO::Socket::SSL 2.099 is installed.
- IMAP: Mail::IMAPClient 3.43. idle, idle_data, and done exist. NOTIFY is sent on the socket that stays in the select set. Otherwise one IDLE connection per folder.
- mbsync: /usr/local/bin/mbsync channel:box [channel:box ...]. isync-1.5.1p0 is installed. Same-channel folders that are ready within one 5s window share that argv. wait seconds (the max in the batch) happen in the child after the 5s. No concurrency cap. Child closes inherited descriptors.
- Syslog: ident imapidle, options cons,pid, facility mail.
- After startup, a failed account, socket, pass_cmd, or mbsync does not exit the process. The loop exits only on SIGTERM or SIGINT (exit 0). SIGHUP re-reads the config on the next wake (within about 30s) and does not exit. A bad file is logged and the running accounts stay. Server, port, user, secret, or channel changes reconnect that account. Folder names and priorities apply in place; a new folder without NOTIFY is connected on that wake. SIGINFO (Ctrl-T) prints state to stderr when -d, and to syslog when daemonized: accounts, connections, per-folder priority and mbsync timing, and mbsync children. Backoff is remembered on the account (5s, x1.5, cap 900) and does not sleep the other accounts.
- IDLE is refreshed about every 30s with DONE then IDLE. NOOP is not sent during IDLE. NOTIFY connections get NOOP on that timer.
- Priority is the minimum time between mbsync runs for one folder (2026-11-10): 1 or less → 7s; 2 → 42s; 3 → 128s; 4 → 256s; >=9 → 3600s; else 180+(priority-3)*120, so 5 is 420, 6 is 540, 7 is 660, and 8 is 780. A ready folder's event opens a 5s channel window (not restarted by later events). An event inside the minimum gap stays pending and is scheduled when the gap ends, with no extra 5s unless another folder's window is already open. No event during the gap leaves the folder ready for the next event. IDLE keepalive (`* OK Still here`), continuations, and tagged replies do not schedule mbsync. EXISTS, EXPUNGE, FETCH, RECENT, VANISHED, and STATUS do. DONE/IDLE refresh is about every 30s, not on every read.
- wait (seconds, default 0) sleeps in the mbsync child after the 5s combine, not in the IMAP loop.

Config shape the script reads
- One INI section per account. Required: server, user, mbsync_channel, and exactly one of pass or pass_cmd. port defaults to 993. Missing required keys exit 1.
- folder0, folder1, ... value is NAME or NAME;priority=N. Numbers start at 0 and have no gaps. Only the priority suffix is read. Missing suffix → priority 5.
- If no folderN keys: folder (default INBOX) and priority (default 5).
- Every folder in a section shares that section's mbsync_channel.
