Project facts (sourced 20261109, updated the same day)
- Program file: imapidle. Perl, ISC header, Copyright (c) 2026 Todd T. Fries. Renamed from imap-idle-notify. ~/bin/imap-idle-notify is still the old copy and has not been replaced.
- Invocation: imapidle [-dvn] [-c file]. -n loads config and ~/.local/imapidle into memory, watches mailboxes from a sibling idle process, logs the mbsync it would have run, and waits the predicted seconds plus or minus about a quarter of that time (five seconds when that command has no average). State stays in memory. The control socket stays closed, so it can run beside the live daemon (2026-11-18). A pulse account is a separate process that logs in and runs STATUS. The hub does not open that socket. The first STATUS count is a baseline and does not start the logged sync (2026-11-20). Without -n the same processes are the daemon: the hub runs mbsync, writes ~/.local/imapidle, opens the control socket, and watches the shutdown file. It does not open an IMAP socket. Watched folders stay in IDLE in their own process and re-arm about every 30s. A pulse account's process runs STATUS. A tracked mailbox on an account that has one of those processes is classified from that STATUS before mbsync; an account with no IMAP process is still synced on its timer. --tunnel is still the single process (2026-11-20). Also `imapidle --tunnel section [-c file]`, which logs in as that one section and exits. Default file ~/.config/imapidle/imapidle.conf. -d stays in the foreground and copies logs to stderr. -v logs `* OK Still here` and `IDLE re-armed`. Those two stay quiet by default (2026-11-10). Without -d the starting process logs `-> PID` and exits. PID is the process that keeps running. A failed fork is one error line from that starting process (2026-11-13). mbsync is forked only after that handoff. A child of the starter is reparented to init, and the daemon still had it in the child table: wait4 returned ECHILD, shutdown said `waiting on N mbsync`, and a due folder made the select timeout 0 so the process spun. Those entries are now logged `gone` and dropped, the wait sleeps at least one second, and shutdown can exit (2026-11-13). A shutdown file at startup exits before a mailbox is opened and before daemonize. The check runs again before each account, before each further mailbox, and when an IMAP wait is entered, so a login already started does not continue into IDLE. An mbsync this process already started still finishes (2026-11-14). A due tracked folder does not make the select timeout 0 while its channel is already syncing or every slot is in use. The loop sleeps and a child exit wakes it. A due folder list does not busy-poll either (2026-11-14). The announced version is `$VERSION`, currently 0.3 (2026-11-16), and that is the version in the ID command (2026-11-14).

- IMAP connection limit (2026-11-16 12:53 CST): a refusal such as Dovecot `Maximum number of connections from user+IP exceeded (mail_max_userip_connections=N)` is not a connect failure. The cap is how many of this process's sessions for that server, port, and user were already open. The number in the message is stored as server_max and is not the cap, because mbsync and other clients share the budget. The table is ~/.local/imapidle/conn-limit (mode 0600), one row `server port user cap probe server_max`. It is loaded at startup and written on change and on shutdown. A reload does not clear it. Once a week, plus the quarter spread, one extra login is allowed. Success raises the cap by the new open count and schedules another week. A refusal keeps the cap and schedules another week. An authentication or timeout failure does not change the cap and does not spend the week. The refusal does not call mark_retry, does not drop sessions already open, and does not open the rest of that user's folders in the same pass. A later quiet skip is not logged. The log line is `name: connection limit N, server M, probe in Ns`, and it omits `server M` when the message had no integer. The loop keeps its 30s ceiling while that probe is further out, and wakes sooner when the probe is inside 30s. A dropped session can still be replaced up to the cap, because the week is not stored in next_try. `--tunnel` and login_imap itself are not capped. imapidlectl nodes are `limit.SERVER.PORT.USER.cap`, `.probe`, and `.server_max`. cap and probe can be set, and those writes are stored in conn-limit. - After startup, a failed account, socket, pass_cmd, or mbsync does not exit the process. The loop exits 0 on SIGTERM, SIGINT, or a file ~/tmp/shutdown, ~/tmp/shutdown.mail, or ~/tmp/shutdown.imapidle. The handler sets a flag and does not exit. When that shutdown is noticed, each open IDLE session is ended with DONE and then LOGOUT, and each NOTIFY session with LOGOUT. A session that is already dead is closed without those commands (2026-11-12). In-flight mbsync then finishes, stats are written, and the log says `shutdown complete`. An account that has never monitored a mailbox is paused after 5 consecutive failures. The first pause is 1800s. The failure count and the connect backoff are reset, and it tries again when the pause ends. Another five failures pause for one and a half times as long, rounded. A step that would pass 43200s is not taken, so the pause stays on the last step under 12h. A successful monitor clears that ladder. SIGHUP enables it and starts the ladder over at 1800s (2026-11-12). A failed mbsync does not disable the account.

The log says `pause file PATH detected, idling operations` once, then `pause cleared, mbsync resuming` when all three are gone. Events stay queued and catch up after that. - IDLE is refreshed about every 30s with DONE then IDLE. NOOP is not sent during IDLE. NOTIFY connections get NOOP on that timer. The re-arm notice and `* OK Still here` are logged only with -v (2026-11-10). A failed re-arm is still a warning. DONE, IDLE, and LOGOUT are not sent once the socket is already dead, so Mail::IMAPClient does not dump a not-connected stack (2026-11-12).
- Priority is the minimum time between mbsync runs for one folder (2026-11-10): 1 or less → 7s; 2 → 42s; 3 → 128s; 4 → 256s; >=9 → 3600s; else 180+(priority-3)*120, so 5 is 420, 6 is 540, 7 is 660, and 8 is 780. A ready folder's arrival opens a 5s channel window (not restarted by later arrivals). An arrival inside the minimum gap stays pending and is scheduled when the gap ends, with no extra 5s unless another folder's window is already open. With no arrival during the gap, the folder stays quiet until new mail arrives or its resync time elapses. The default resync is 43200s (12h), minimum 60, and the priority gap still applies (2026-11-16 08:37 CST). IDLE keepalive (`* OK Still here`), continuations, and tagged replies do not schedule mbsync. The keepalive and the re-arm notice are logged only with -v. Continuations and tagged replies stay in the log. On an IDLE folder, EXISTS schedules only when the announced total is higher than the remembered total. EXPUNGE and a live VANISHED lower that total and do not schedule. VANISHED (EARLIER) is history. FETCH and RECENT leave the total and do not schedule. A `*` or bad VANISHED token forgets the total so the next EXISTS schedules once. The SELECT EXISTS is the baseline, and SELECT's UIDNEXT is remembered with it. A dropped session remembers that total for the account and folder. The next SELECT schedules one sync when the new total is higher, and does not when the total is the same or lower. After an IDLE or poll folder's mbsync exits 0, STATUS (MESSAGES UIDNEXT) replaces both numbers. A higher total schedules another sync. A higher UIDNEXT with no higher total schedules one confirmation sync. A confirmation that only moves UIDNEXT again stores it and does not schedule, so a flag rewrite cannot requeue forever (2026-11-16 09:22 CST). hyperdelete=yes (account key, or the global section when the account omits it) also schedules a removal, including a smaller EXISTS. NOTIFY still schedules EXISTS, EXPUNGE, FETCH, RECENT, VANISHED, and STATUS. STATUS on IDLE still schedules. The poll fallback and the empty-mailbox probe keep their own clocks. DONE/IDLE refresh is about every 30s, not on every read.

Config shape the script reads
- Every section requires type= global, server, account, idle, or pulse (case-insensitive). At most one global. More than one server, account, idle, or pulse section is allowed. A missing or unknown type rejects the file. The section name is a label. global holds the old track keys plus tunnel, tunnel_timeout, and mbsyncrc. server is host, port, and proto tls, starttls, or notls. tls is implicit TLS and the default, port 993. starttls reads the clear greeting, sends STARTTLS, then the same certificate checks, default port 143. notls is cleartext, logs one line that the account is cleartext, and collects no certificate. The default is never notls. A set port is used as written. An account may override port or proto. A proto override keeps an explicit server port. A server value that is not a section name stays a hostname with tls and port 993. type=server is not connected by itself. account holds the login and the mbsync channel, defaults mbsync_channel to the section name, does not IDLE, and opens no socket until an idle or pulse section names it. An idle section sets channel to an account name and puts folderN on the idle section. Login keys on an idle or pulse section reject the file. An idle section with no channel= is missing channel. The idle section name is only a label. Both channel and server on one idle section rejects the file. pulse has no folderN. channel0, channel1, ... name account sections. A pulse with no channelN is missing channel0. folderN starts at 0 and a gap is rejected. A pulse name that is not an account rejects the file. The same account on idle and pulse, or on two pulse sections, rejects the file. Two bound idle or pulse accounts that share an mbsync channel reject the file. folderN on an account or pulse section rejects the file. An account requires server, user, and exactly one of pass or pass_cmd. An omitted mbsync_channel becomes the account name. port follows proto when omitted. Missing required keys exit 1 (2026-11-16 12:22 CST). disabled = yes keeps the section without connecting or checking those keys. Any other value leaves it active.
